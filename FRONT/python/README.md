# ALEM PROTOCOL / Aqylman Desktop

Нативный интерфейс на **Python + PySide6 (Qt)**. Открывается отдельным окном,
не использует браузер, NiceGUI или React. Светлый стиль и рабочие сценарии
перенесены из прежнего макета ALEM; компоненты заново реализованы для Qt.
Существующий React/Tauri в `FRONT/src` сохранён без изменений.

## Запуск на этом Mac

1. Открыть папку репозитория.
2. Дважды нажать `Запустить ALEM.command` в корне.
3. Дождаться окна ALEM PROTOCOL. Первый запуск устанавливает зависимости.

Терминал с запуском оставьте открытым. Закрытие окна приложения останавливает
его backend. Записи и протоколы сохраняются между запусками.

Для редактирования: VS Code > File > Open Folder > вся папка репозитория.
Терминал VS Code: `python3 launch_desktop.py` (Python 3.10–3.13).
Windows: `Запустить ALEM.bat`; Windows-сборка отдельно не проверялась.

Это запуск из исходников, **не автономный подписанный установщик**.
Для распространения без Python ещё потребуется сборка и подпись .app/.exe.

## Что подключено

- Список, поиск и фильтрация встреч из FastAPI.
- Создание и загрузка файлов в backend, прогресс и ошибки обработки.
- Настоящий плеер Qt: пауза, перемотка, скорость, громкость и mute.
- Индикатор уровня на основе декодированного звука, а не декоративной анимации.
- Запись с микрофона: выбор устройства, согласие участников, усиление 0–200%,
  индикация, WAV на диск, затем импорт в backend. Максимум 30 минут / 480 МБ.
- Правка поручений (текст, исполнитель, постановщик, дата, статус), сохранение
  через PATCH; переименование участников; экспорт PDF/DOCX через API.
- Несохранённые правки не теряются при переключении поручений. При выходе
  есть подтверждение. Повторный анализ предупреждает о замене исправлений.

## Честные ограничения

Backend по умолчанию работает в `MOCK_MODE=true`: возвращает одинаковый
пример для любой записи. Это явно показано в окне. Настоящее распознавание,
диаризация и извлечение поручений ещё относятся к работе backend-команды.
Переключение `MOCK_MODE=false` само по себе их не реализует.

Zoom/Teams пока поддерживаются как импорт сохранённой записи или вход
установленного пользователем виртуального аудиоустройства. Бота, захвата
системного звука напрямую и живых субтитров нет. Микрофон требует разрешения
ОС и согласия участников; проверяется вручную на целевом устройстве.

Интерфейс этой версии на русском. Казахская локализация прежнего веб-макета
не перенесена; обработка смешанной RU/KK-речи зависит от будущего backend.
Удаление/добавление поручений и редактирование итогов не показаны: в API нет
соответствующих операций. Статусы поручений: `open`, `confirmed`, `done`.
Переименование спикера не меняет автоматически исполнителя поручения.

## Структура

```text
launch_desktop.py       запуск обоих процессов и их остановка
FRONT/python/
  desktop.py           окна, таблицы, формы и состояния
  audio.py             плеер, WAV-запись, уровни звука
  api.py               адаптер API backend
  jobs.py              фоновые запросы вне потока интерфейса
  theme.qss            оформление
  requirements.txt     зависимости Python UI
```

Frontend не читает SQLite напрямую. API использует только localhost.
`BACKEND` и `FRONT` имеют отдельные virtualenv. API-ключи не нужны.
Начальная установка пакетов требует сети; работа приложения не требует
интернета и ничего не передаёт в облако.

Данные: `BACKEND/meeting_protocol.db`, `BACKEND/uploads`,
`FRONT/.desktop-data/recordings`. Журналы: `.desktop-data/backend.log` и
`.desktop-data/desktop.log`. Данные, окружения и журналы исключены из Git.

Два небольших дополнения backend: `GET /api/v1/meetings/{id}/media`
(только файл в uploads, с HTTP Range для перемотки) и шрифт Arial для PDF
на macOS. Остальные операции используют существующий контракт API.

## Проверки

```sh
cd BACKEND
.venv/bin/python -m pytest -q
cd ..
FRONT/.desktop-env/bin/python -m unittest discover -s FRONT/python/tests -v
```

Для ручной проверки: создать встречу с настоящим аудиофайлом, прослушать,
изменить громкость и скорость, обработать (демо), исправить поручение,
переоткрыть встречу, экспортировать оба документа. Затем записать короткий
фрагмент микрофона и проверить воспроизведение. Записи тестов не коммитить.
